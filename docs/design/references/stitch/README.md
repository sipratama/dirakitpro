# Stitch design references — Homepage

This folder holds normalized, approved visual references generated by Stitch (an
AI design-generation tool) for the public Homepage (`/`). **These files are
reference material only — not production source code.**

## Authority order

When anything here conflicts with another source, resolve in this order
(highest wins):

1. `CLAUDE.md`
2. `docs/VISUAL_POLISH.md`
3. `docs/design/DESIGN.md` (and the tokens it defines in `tailwind.config.ts` /
   `globals.css`)
4. Actual product/business behavior (PRD, existing domain code)
5. The approved PNGs in `homepage/*.png` below
6. The generated HTML in `homepage/html/*.html`

Product/business behavior always wins over visual reference — a Stitch mockup
never justifies inventing a route, a stat, or a feature that doesn't exist.

## Known corrections vs. the raw Stitch screenshots

The following do not carry over into production and must not be copied
verbatim from the HTML/PNG:

- The hero mock shows a demo learner "Dimas Pratama" / `dimaspratama.dev`.
  Production uses **Singgih Pratama** / `singgihpratama.com` (matching the
  already-correct `why-dirakitpro.png` reference).
- The hero mock includes "Bergabung dengan 10.000+ perakit lainnya." This is a
  fabricated stat and is dropped, with no replacement number invented.
- The FAQ mock's second answer claims "komunitas perakit siap membantu." No
  such community/mentoring feature exists in the current product — production
  copy is reworded to describe what the product actually does.
- Build Discovery prices/durations in the mock are placeholder prototype data.
  Production pulls real values from `getPublishedCourses()`
  (`apps/web/features/catalog/get-published-courses.ts`).
- The footer mock links "Tentang Kami", "Kebijakan Privasi", "Syarat &
  Ketentuan", and "Bantuan" — none of these routes exist in the app. Production
  omits them rather than linking dead routes.

## How to use this when implementing

- Treat the PNG as the primary reference for layout/spacing intent and the
  HTML as a secondary detail reference only — never copy the HTML into a
  component wholesale.
- Rebuild every section using the app's real Next.js/Tailwind conventions:
  the tokens in `tailwind.config.ts`, the existing component patterns in
  `apps/web/components/`, and the app's accessibility and responsive
  conventions. A Stitch layout is a starting point, not a contract.
